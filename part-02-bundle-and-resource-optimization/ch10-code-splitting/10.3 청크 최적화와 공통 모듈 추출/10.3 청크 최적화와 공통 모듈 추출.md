# 10.3 청크 최적화와 공통 모듈 추출

## 개요

코드를 어디서 분할할지 결정했다면, 이제 번들러가 생성한 청크를 최적화해야 함

### 효과적인 청크 최적화 : 세 가지 목표의 균형

1. 중복 제거
2. 캐싱 효율
3. 청크 크기와 개수의 균형

## 벤더 청크 분리 전략

- 외부 라이브러리를 적절히 묶어서 불필요한 다운로드를 줄이고 캐시 효율을 높이려는 최적화 방법
- 가장 기본적이면서도 효과적인 최적화
- node_modules에서 가져오는 서드파티 라이브러리를 애플리케이션 코드와 분리 → 라이브러리는 거의 변경되지 않으므로 오랜 기간 캐시될 수 있음
- Vite : 기본적으로 벤더를 자동으로 분리하지 않음
  - 청크 크기가 중요한 이유 : 단순히 다운로드 시간 때문만이 아니라, 자바스크립트는 다운로드 후 파싱과 컴파일 과정을 거치는데, 이 과정은 파일 크기에 비례하여 시간이 증가함
  - vendor : 외부에서 가져다 쓰는 라이브러리 코드

### 안티패턴 3가지

- 안티패턴 1 : 모든 라이브러리를 개별 청크로
- 안티패턴 2 : 거의 사용하지 않는 라이브러리를 공통 vendor에 포함
- 안티패턴 3 : 버전이 자주 변경되는 라이브러리를 vendoer에 포함

### 효과적인 벤더 청크 분리 기준

- 크기 : 최소 20~30KB 이상의 라이브러리만 별도 청크로 분리
- 사용 빈도 : 모든 페이지 또는 대부분의 페이지에서 사용하는 라이브러리만 벤더 청크로 분리
- 업데이트 빈도 : 거의 변경되지 않는 라이브러리(리액트, lodash)는 벤더 청크로 분리하고, 자주 업데이트되는 라이브러리는 별도로 관리
- 관련성 : 함께 사용되는 라이브러리는 하나의 청크로 묶음

## 청크 개수와 크기의 균형

### 구글의 연구가 제시한 유용한 기준

- HTTP/2 환경에서 초기 로드 시 약 25개 이하의 리소스를 요청하는것이 최적
  - 이 범위 내에서는 FCP(First Contentful Paint)와 로드 시간이 거의 동일하게 유지됨
- 각 청크는 최소 20~30KB 이상 권장

### 실제 프로젝트에서 최적의 청크 구성을 찾는 단계

- 1단계 : 현재 청크 구성 분석
- 2단계 : Rollup Visualizer로 청크 내용 분석
- 3단계 : 청크 분리 전략 수립
  1. 무거운 라이브러리를 분리
  2. 공통 모듈 추출
  3. 사용 빈도 낮은 코드는 지연 로딩
- 4단계 : 실제 성능 측정
  - 라이트 하우스나 WebPageTest로 실제 로딩 성능 측정
- 5단계 : 캐시 효율 확인
